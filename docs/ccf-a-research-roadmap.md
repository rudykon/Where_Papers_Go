# Where Papers Go 研究化与 CCF-A 投稿路线

> 文档状态：证据冻结草案；P0 和 M3 工程完成，SCOPE-Rank 科学成功门未通过，专家人评待执行
> 状态更新：2026-08-30（Asia/Shanghai）
> 主目标：SIGIR Full Paper
> 原则：产品能力可继续增强，但论文主结论必须来自可复现、无泄漏的离线实验。

## 1. 投稿判断

Where Papers Go 已经是一个较完整的开放候选投稿地检索系统，但当前还不宜把 SCOPE-Rank 包装成 CCF-A Full Paper 的成功方法贡献。P0 已建立可复现、Search-free、零 critical leakage 的全库离线基线；M3 强基线工程、统一评测和配对统计已完成。然而，SCOPE-Rank full 在暴露开发集和有限定的未来评测中都是显著负结果，专家盲评尚无真实标注。LightRAG、稠密向量、属性图、LLM 和 Search API 的产品集成本身仍不能替代方法有效性证据。

推荐将研究问题定义为：

> **Coverage-Aware Open-World Venue Retrieval under Ambiguous and Constrained Research Intent**
> 在收稿范围不完整、候选空间开放、用户表达模糊且带有硬约束时，如何给出全面、准确、可校准且有证据来源的投稿目标排序？

SIGIR 是当前最匹配的主目标，因为论文的核心应当是信息检索、排序、推荐和评测。可另行准备 Demo 用于展示系统，但根据 CCF 目录说明，Demo、Short、Workshop 等非 Full/Regular Paper 不按 CCF-A Full Paper 计入。投稿前应再核对当年的 [CCF 目录与说明](https://www.ccf.org.cn/Academic_Evaluation/By_category/) 以及 [SIGIR Full Papers Track](https://sigir2026.org/en-AU/pages/submissions/full-papers-track)。

## 3. 任务定义

设候选投稿地集合为 \(V\)，用户输入为 \(x\)，硬约束为 \(c\)，截止时间为 \(T\)。系统将 \(x\) 解析为主题、任务、方法、数据/对象、模态、稿件类型和排除条件等切面 \(f(x)\)。对每个投稿地 \(v\)，只能使用截止 \(T\) 可用的简介、aims & scope、分类、历史论文和图关系形成档案 \(p_v^T\)。

输出不只是排序 \(\pi(x,c,V)\)，还包括：

- 候选投稿地的相关性分数和不确定性；
- 硬约束是否满足；
- 证据的来源、时间和覆盖状态；
- 证据不足时的拒答或扩大检索决策。

历史真实期刊只是一个弱正标签，不等于唯一合理答案。因此论文同时建立两个任务：

1. **Historical venue recovery**：用大规模时间分割数据测量真实发表期刊的恢复率。
2. **Prospective suitability**：用专家多级标注测量 Top-K 投稿地的实际适配性、约束一致性和证据充分性。

## 4. 研究问题

- **RQ1：多通道召回。** 开放候选下，词法、稠密向量、LightRAG/属性图和学科路由是否互补？
- **RQ2：自适应路由。** 基于查询模糊度、切面缺失和证据覆盖度学习通道配额，能否超过固定的 `12/8/6/6/4/4` 候选配额？
- **RQ3：范围不完整性。** 显式建模 scope 覆盖与不确定性，能否降低对资料丰富头部期刊的偏好？
- **RQ4：模糊和跨语言鲁棒性。** 在中英文、简略描述、跨学科和缺少方法等信息条件下，方法是否保持稳定？
- **RQ5：校准与拒答。** 置信度能否正确反映失败风险，并在给定覆盖率时降低错误推荐？
- **RQ6：效率与质量。** 并行召回、批处理、缓存和候选裁剪能否在不降低召回/排序质量的前提下降低冷启动延迟和外部 API 调用量？

## 5. SCOPE-Rank 方法蓝图

**SCOPE-Rank** 是本项目实现并评测的方法名，表示 *Scope- and Constraint-aware Open-world Paper-to-venue Evidence Ranking*。它不是对固定融合参数的重命名，而是由以下可消融组件组成的正式研究实现。

当前工程已覆盖 `QueryProfile` 路由画像、`AdaptiveBudgetAllocator` 确定性自适应预算、`LinearSoftmaxFusion` 仅训练集学习融合、`SelectiveCalibrator` 选择性校准、缺失感知、硬约束与来源解释，并完成了统一消融。但“实现完成”与“科学有效”必须分开：full 方法在开发集和有限定未来评测中均显著更差，因此下文组件只能作为已实现、已检验但未验证增益的方法设计。

### 5.1 Facet parser

LLM 将模糊输入转换为结构化切面，但保留原文、每个切面的置信度和可选的多义解释。硬约束单独表示，不允许 LLM 在排序中“软化”。

### 5.2 Provenance-aware venue profiles

对 aims & scope、官方类别、历史论文和图关系保存 `source`、`retrieved_at`、`valid_at`、`license` 和 `confidence`。缺失 scope 不等于主题不匹配，而是显式的未知状态。

### 5.3 Complementary retrieval channels

所有通道使用同一候选目录和同一时间快照：

- BM25/词法检索；
- bge-m3 或科学文献表示的稠密召回；
- LightRAG mix 和属性图近邻；
- 学科、方法、稿件类型等分类路由；
- 仅用于产品在线增强轨道的 Search 证据，不进入论文主离线榜。

### 5.4 Coverage-aware adaptive router

使用查询切面完整度、中英文标识、主题熵、各通道头部分布和档案覆盖度，预测各通道的候选配额或门控权重。训练只使用训练/验证集，不根据测试金标调整。

### 5.5 Constraint-preserving learned fusion

以可学习排序替代当前固定 `vector=6`、`graph=4`、`LightRAG=5` 一类全局启发式分数。特征包括多通道排名/分数、切面覆盖、来源时间、档案缺失、约束状态和期刊活跃性。硬约束先做确定性过滤，再对合法候选排序，并报告零违规率。

### 5.6 Calibration, abstention and evidence

将原始排序分数校准为可解释的置信度。当头部候选分数接近、范围证据缺失或切面冲突时，触发扩展检索、向用户追问或明确拒答。解释仅引用真正参与排序的冻结证据。

## 7. 时间冻结与无泄漏协议

### 7.1 数据分割

1. 先选定一个不可变的时间切分点 \(T\)，再构建数据，不根据结果修改切分点。
2. 训练和候选档案只使用 \(T\) 之前的记录；测试论文的首次公开时间在 \(T\) 之后。
3. DOI、标题规范化哈希、摘要近重复和预印本—正式版关系全部用于跨集去重。
4. 期刊档案中建立的历史论文表示必须排除测试论文及其近重复版本。

### 7.2 候选档案冻结

主榜优先使用能够证明 `valid_at <= T` 的官方 scope 快照。无法获取历史官网快照时，应用 \(T\) 之前的历史论文和目录元数据构建期刊档案，而不应将“当前网页抓取时间”误当作“历史生效时间”。

所有期刊必须经过相同的档案构建规则。禁止优先补全测试金标期刊；如资源不足，应在不知道金标的情况下按期刊 ID 稳定哈希或学科分层随机抽样，并报告覆盖差异。

### 7.3 Search 与 LLM 隔离

- 论文主榜不调用实时 Search API，不因配额、搜索索引更新或网络错误改变结果。
- 产品在线轨道仍可强制使用 Search API，但查询只能由结构化主题切面生成，不携带 DOI、原标题、作者、金标期刊或长摘要独特原句。
- 保留原有 DOI、近似标题和金标期刊名泄漏审计，并追加查询原句重合率审计。
- 冻结 LLM 提供商、模型标识、版本/日期、系统提示词和解码参数。公开论文可能被模型训练数据记忆是无法完全排除的残余风险，必须写入局限。

### 7.4 不可见测试集

验证集用于调参、早停和阈值选择；主测试集在方法和主指标冻结前不对开发者暴露金标。评测脚本输出汇总指标，等主实验锁定后再开封逐条误差分析。

## 8. 强基线

每个基线必须使用相同的 20,087 候选空间、相同的期刊档案快照和相同的训练数据。不允许新方法独占更完整的 scope 或额外金标信息。

| 类型 | 基线 |
| --- | --- |
| 非语义对照 | 随机排序、训练集流行度、分学科流行度 |
| 词法 | TF-IDF/BM25 全库检索 |
| 通用稠密 | bge-m3 单通道 |
| 科学文献表示 | SPECTER2、SciNCL（以可复现的官方模型和输入协议为准） |
| 精细互动 | ColBERT 或 cross-encoder 重排 |
| 经典混合 | BM25 + dense 的 RRF/线性融合 |
| 图和 RAG | 属性图单通道、LightRAG mix 单通道 |
| LLM | 向 LLM 提供闭合候选列表的 LLM-only 排序；不允许它直接上网查原论文 |
| 现有系统 | 当前固定权重 + 固定多通道配额，作为主工程基线 |
| 新方法 | SCOPE-Rank 和其所有消融版本 |

如某个模型因许可、硬件或输入长度无法运行，需在论文中事先解释，而不是事后只保留弱基线。

## 9. 指标与统计

### 9.1 主指标

- 单一历史正标签：Hit/Recall@1、3、5、10、20、50，MRR@10。
- 专家多级标签：nDCG@5/10，Recall@K，以及具有多个合理投稿地时的 MAP。
- 召回—排序分层：每个通道 Recall@K、并集 Recall@K、重排前后的增益。

### 9.2 可靠性、约束与系统指标

- 校准：ECE、Brier score、reliability diagram。
- 选择性预测：risk–coverage curve，以及指定覆盖下的错误率。
- 约束：Top-K 硬约束违规率（目标为 0）。
- 覆盖：目录映射率、期刊档案覆盖率、官方 scope 覆盖率、无证据推荐率。
- 稳定性：相同意图改写的 Top-K Jaccard/RBO，以及中英文互译一致性。
- 延迟与成本：冷/暖启动 p50、p90、p99，每查询 LLM/Search 调用数、token 和金额。
- 可用性：失败率、超时率、缓存命中率；离线主榜应为 0 外部 API 失败。

主指标在开启不可见测试集前预注册。报告至少 95% bootstrap 置信区间；同一查询上比较方法时使用配对置信区间和适合排序指标的随机化/重抽样检验，同时给出效应量。学科、分区、语言和模糊度结果作为分层指标，不用小样本分层百分比宣称普遍偏好。

## 10. 消融和鲁棒性实验

### 10.1 方法消融

- 移除 Facet parser，直接编码原文。
- 将自适应路由替换为当前固定 `12/8/6/6/4/4` 配额。
- 分别移除 BM25、dense、LightRAG、属性图和学科路由。
- 将可学习融合替换为 RRF 和现有固定加权。
- 移除 scope 覆盖/缺失特征。
- 移除不确定性校准与拒答。
- 将硬约束从确定性过滤改为软分数，用于证明约束保持的必要性。
- 移除来源时间/可信度特征，观察过时证据影响。

### 10.2 鲁棒性与公平性分层

- 精确标题+摘要、仅摘要、短描述和极模糊意图。
- 中文、英文和平行互译。
- 单学科、跨学科、方法主导和应用主导。
- scope 随机缺失与按学科/出版社结构性缺失。
- 头部/长尾期刊、Q1–Q4、9 个宽学科。
- 主题外干扰、切面冲突、缺少方法/对象和否定表达。

## 11. 专家人评

当前状态是“工具与材料完成，人工评测待执行”：已确定性抽取 250 条查询，对四种方法的 Top-K 合并去重后得到 6,129 个评审项，并生成 3 份专家分配、进度保存、审计和导出材料。真实标注数为 0，因此 Krippendorff's alpha/Fleiss' kappa 与人评效果均不可用。实际执行仍必须遵守以下冻结协议：

1. 按学科、语言、模糊度和跨学科性分层抽取 200–300 条查询。
2. 每条查询合并强基线与 SCOPE-Rank 的 Top-5 或 Top-10，去重、随机打乱，隐藏系统来源和原始排名。
3. 每条由至少 3 名相关领域评审独立打分：主题适配 0–3、稿件类型适配 0–2、约束通过/不通过、证据充分 0–2。
4. 提前定义评分指南和边界案例，先做小规模校准轮，再冻结标注规则。
5. 报告 Krippendorff's alpha 或加权 kappa；分歧样本由未参与首轮的专家仲裁，同时保留原始分歧。
6. 人评同时记录专家所熟悉的学科与期刊，并进行匿名化；不收集与任务无关的个人信息。

## 12. 性能升级的评测契约

“更快”必须在同等候选和同等精度下评估，不得用减少候选、跳过强制通道或隐藏失败样本换取延迟数值。

- 并行化、批编码、缓存、文件内存映射等确定性优化：冻结查询上的候选 ID 与排序必须一致，并单独报告冷/暖缓存。
- ANN、量化、候选裁剪等近似优化：默认不进入生产主路，直到在冻结验证集上通过预注册的非劣性检验；同时保留精确回退。
- 远程 LLM/Search 调用：并发数和重试策略必须记录；配额失败不从分母中删除。
- 推荐优化的主守门指标为 Recall-pool@40/50 和最终 nDCG/Hit@K；延迟是次级守门指标。

性能报告至少包含：单 worker 与目标并发度、冷/暖缓存、CPU/GPU 型号、内存/显存、请求长度、p50/p90/p99、吞吐量、错误率和每查询成本。

## 13. 实验组织与可复现性

建议将产品运行与论文实验隔离：

```text
research/
├── configs/          # 数据、方法、基线和消融的声明式配置
├── data_cards/       # 数据卡、许可、时间窗和哈希
├── protocols/        # 无泄漏、人评和统计协议
├── runs/             # 运行清单和汇总；大型中间产物不提交 Git
└── README.md
```

每次运行保存：

- Git commit、数据清单 SHA-256、候选目录哈希和配置哈希；
- 随机种子、包锁定文件、模型精确标识和硬件；
- 训练/验证/测试集的不可变 ID 清单；
- 逐查询候选、通道分数、约束决策和失败类型；
- 一条命令可重建的汇总表和图，不手工修改数字。

未记录的远程模型更新、Search 索引更新和缓存命中都可以改变结果，所以它们只能出现在产品增强或单独在线轨道中。

## 15. 论文结构建议

1. **Introduction**：开放候选、模糊意图、约束和范围缺失带来的问题。
2. **Related Work**：学术投稿地推荐、学术检索、开放世界推荐、知识图/RAG、不确定性校准。
3. **Task and Benchmark**：形式化定义、数据卡、时间冻结、泄漏协议。
4. **SCOPE-Rank**：切面解析、多通道、自适应路由、约束融合、校准。
5. **Experiments**：强基线、主结果、消融、鲁棒性、性能/成本。
6. **Human Evaluation**：多相关性、评审一致性和定性误差。
7. **Limitations, Ethics and Broader Impact**：决策辅助边界、数据偏差、商业目录与语言/学科不均衡。
8. **Reproducibility**：配置、快照、代码、运行成本和授权边界。

现有论文表述必须正面报告 SCOPE-Rank full 在开发集和有限定未来评测中的显著负结果，以及 linear/RRF 对 LightRAG 的不显著比较。不得声称“state of the art”、“first”、“significant improvement”或已完成专家验证。

## 16. 数据版权、隐私与 AI 使用

### 16.1 版权与抓取

- 仅采集研究所需的元数据，不抓取或再发布 PDF/出版社全文。
- Crossref 可访问元数据不意味着所有摘要都允许再分发。公开人工或派生数据前要逐源核对许可；无明确许可时只公开 DOI/稳定 ID、构建脚本、哈希和聚合指标。
- aims & scope 保存 URL、抓取时间和必要的短摘要/派生特征；遵守站点条款、robots 政策和访问频率限制。
- 商业 JCR/CAS 目录的再分发权与研究使用权分开审核；开源代码的 Apache-2.0 许可不会自动覆盖第三方数据。

### 16.2 隐私与安全

- 不将未发表稿件默认发送到 LLM 或 Search 第三方 API；需要用户明确知情，并提供本地/脱敏模式。
- 日志不保存用户原始未公开摘要；如必须保存，设定最小留存期、访问控制和删除流程。
- API key、专家身份和原始人评记录不进入 Git；研究产物中只保留匿名 ID 和必要聚合。
- 系统是决策辅助而不是录用或发表保证，界面与论文都应明示这一边界。

### 16.3 生成式 AI

- 记录 LLM 在数据清理、切面生成、排序、代码和论文写作中的确切作用。
- 实验模型与写作辅助模型分开记录；保存允许分发的提示词、版本和解码参数。
- AI 不作为作者，不替代人工核对引用、数据来源、数值和新颖性声明。
- 按投稿时 SIGIR/ACM 的最新政策披露 AI 使用；本文档不替代当年的正式政策。
